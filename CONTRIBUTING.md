# Contributing

Read README.md and the relevant OpenSpec change before suggesting changes. Install with `bun install --frozen-lockfile --ignore-scripts`; run the development checks documented in README.md.

Keep proposals focused on a demonstrated OpenSpec review need. Describe expected behavior, relevant failure cases and how the change can be verified. Avoid unrelated cleanup and speculative abstractions.

Use pull requests for source changes. State what changed, the checks actually run and any remaining limitations. Never include credentials, private documents or unredacted local diagnostics.
