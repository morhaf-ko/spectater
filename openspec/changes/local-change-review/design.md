# Design

## Context and authority

The operator authorized the local OpenSpec reader and subsequently requested Bun, current stable dependencies, Clean styling, native Apple typography, contextual comments, a system-aware icon theme control, a favicon and a complete existing-agent handoff. This file, proposal.md, delta specs and tasks.md are the planning authority. docs/workflow.md contains supported usage, not a separate plan. Publication, releases, global hooks and implicit personal skill installation remain outside implementation authority.

## Architecture

A Bun CLI uses native HTTP, crypto, filesystem, subprocess and test facilities with plain local browser assets. unified/remark-parse/remark-gfm provide maintained Markdown AST parsing. OpenSpec remains an external discovery authority; verified contracts are 1.15.0 and 1.16.1. Version pins and supported runtimes live in package.json and the lockfile. No accounts, hosted backend, models, agent API, framework, database, login daemon or repository scanner is involved.

Native context/list/status JSON selects one explicit project/change and preserves an explicit store selector on every applicable call. Use native root provenance, changeRoot, schemaName, artifacts and existingOutputPaths; do not copy schema/glob/status parsing. Refuse unselected global defaults, missing/unsupported CLI contracts, escaping paths and identity changes. Canonical resolved root plus change path identifies review state; worktrees remain isolated and shared stores intentionally share identity. Refresh rediscovers the manifest through the same native contract.

## Source and feedback contracts

Read strict UTF-8 without newline normalization, hash original bytes and retain immutable source snapshots. Offsets are half-open UTF-16 indices; exact selections retain their raw slice. Render restricted AST nodes to escaped DOM with allowed links, inert raw HTML/diagrams and no remote images. Each rendered leaf maps to its source span. Rendered selections intersect mapped leaves in DOM order. Exact boundary leaves use their selected offsets; transformed boundary leaves retain their enclosing source spans. Selections crossing formatting or blocks bind the contiguous source range with enclosing precision. Non-whitespace unmapped boundary text requires Source rather than invented offsets. Source view exposes exact text and line references. Cache current rendering by byte hash/renderer version; saves recheck current file hashes without native subprocesses.

Comments contain an ID, document/path/hash, start/end/slice, rendered quote, prefix/suffix, precision, body, timestamps and open/resolved state. Editing changes the saved body; deletion adds a recoverable deletedAt marker. Submitted batches snapshot entries with monotonically increasing sequence numbers and remain unchanged by later edits/deletes/resolution/reattachment. Removed or ambiguous anchors are orphaned; any changed source makes prior comments stale until explicit reattachment. Retain old anchors and snapshots. No inference of implementation approval or addressed feedback.

Private JSON state lives outside repositories, in an owned directory with owner-only permissions. A per-review exclusive writer lock prevents conflicting servers. Write a same-directory temporary file, fsync, atomic rename and directory fsync before acknowledgement. Reject/preserve corrupt or unsupported state; do not reset or steal locks. State remains until explicit operator removal. Limits: 1 MiB per file, 128 artifact paths, 16 MiB current source, 64 MiB state and 64 KiB web mutation bodies. Closing the browser/process does not remove saved comments/batches. Canonical Markdown and private review-state backups are separate.

## Browser interface and boundary

DESIGN.md owns the operator-selected Clean visual tokens and native Apple font stack. A sun/moon button follows the system initially; Details provides reset. A local script applies root variables before paint without server requests or document replacement. The inline potato mark also supplies the local SVG favicon. CSP allows that fixed local icon, while document images remain unrendered and no generic file route exists.

A native non-modal popover follows valid text selection and focuses the composer. Open it in the next animation frame after mouse release so the gesture's native light-dismiss does not immediately close it. Clamp to the viewport; retain drafts on Escape/dismissal and revision conflict. Optional same-tab sessionStorage caches unsaved drafts; restore an anchor only when its document hash still matches. Saved comments remain disk-authoritative. The sidebar exposes edit/resolve/recoverable delete and immutable batch export. Actual pointer drag and double-click tests supplement synthetic offset fixtures.

Bind HTTP only to 127.0.0.1 on an assigned port. The route uses the encoded change name while canonical review identity remains internal. A per-process fragment capability authorizes requests and is removed from the visible URL after bootstrap. Check Host, mutation Origin, authorization, JSON type and body limits; no CORS. Use CSP, no-referrer/no-store and framing denial. Fixed opaque manifest IDs prevent generic filesystem access; canonicalize/recheck files and reject traversal, escaping symlinks and non-regular files. Local users able to alter this process/files are outside the boundary. macOS is exercised; Linux manual opening/permissions remain unclaimed until exercised and Windows private storage remains unsupported.

## Existing-conversation handoff

The first-party integration asset is a short skill distributed with the CLI, rather than an operator-specific shared skill copied into application agent directories. Its entrypoint asks the existing conversation to read current CLI help/workflow guidance on demand. It preserves project/change/store/config context and never installs itself, hooks or agent plugins implicitly. Instruction following remains a convenience, not a guaranteed OpenSpec draft-completed event.

After drafting and native validation, the agent opens the explicit change in its existing terminal context. The CLI prints the review receipt and local URL. A subsequent open of the same identity/state location attaches to the active process rather than creating another writer. The agent waits with `feedback --review <id> --after <sequence> --wait <seconds>`; each wait is bounded to 55 seconds. If a newer batch is already on disk, return it immediately, even without a running reader. Otherwise wait on the active process. Submission creates the durable batch before notifying waiters. Cursor reads are repeatable and non-destructive; timeout is an explicit result, not a lost batch or permission to run another agent.

The existing conversation reads the batch, explicitly reports work, revises canonical Markdown within its existing authorization, validates it and posts a reply. Selected-change saves refresh automatically; `refresh --review <id>` provides a manual retry. Private local IPC asks the owning process to refresh. A capability-authorized event stream tells browser clients to fetch updated state; preserve written drafts and scroll context and invalidate changed anchors. A bounded native filesystem observer watches only directories under the selected change and coalesces saves; native discovery remains the artifact authority. No polling scanner or second Markdown copy is needed. Refresh and feedback receipt never claim that a model acted or approved work. A stopped agent cannot be woken by this tool; manual export/retrieval stays available.

## Private IPC

Use an owner-only Unix-domain socket directory and deterministic socket name derived from canonical state directory plus review ID. This avoids exposing another TCP service or writing an authentication token into a discovery file. The exclusive review lock owns the socket lifecycle; only owned stale socket nodes may be replaced after acquiring that lock, never regular files/symlinks or a live writer's lock. This implementation supports the same macOS/Linux private-filesystem boundary as state storage.

The IPC protocol is versioned and checks exact review identity. Status returns the active URL/sequence to the same-user caller; refresh returns a revision receipt; next-batch accepts a safe sequence cursor and bounded timeout. Listener disconnect cancels that wait only. Server shutdown completes pending waits explicitly and closes web event streams and IPC before releasing the writer lock. Same-owner filesystem/process access is the authority; browser requests cannot address Unix sockets.

The browser event stream is authenticated with the existing capability through fetch, sends only revision/presence/observation-status notifications, and is bounded by connection limits. It does not continuously poll/hash files, wake models, or mutate sources. Reconnection is explicit on reader refresh; durable batches do not depend on a live stream/listener. Browser and CLI error states distinguish absent listener, timeout, unavailable process and failed refresh.

## Reuse and verification

[OpenSpec configuration](https://openspec.dev/docs/project-config) supplies prompts, not an executable completion hook. [Lavish README](https://github.com/kunchenguid/lavish-axi/blob/69bf3090b24a04773ffd05d2e0b23d91ca41923b/README.md) and its [skill](https://github.com/kunchenguid/lavish-axi/blob/69bf3090b24a04773ffd05d2e0b23d91ca41923b/skills/lavish/SKILL.md) inform thin skill discovery, waiting feedback and refresh continuity; they were source-reviewed, not installed or benchmarked. Its broader HTML workflow does not remove Markdown mapping/revision work. Recogito, spek and SpecLens were considered during exploration; native selection plus AST mapping preserves the smallest dependency surface for this scope. No comparative runtime/token-savings claim is made.

Acceptance: `bun install --frozen-lockfile --ignore-scripts`, `bun run test`, `bun run test:browser`, `bun run test:package`, `bun run smoke -- --fixture local-review --no-open`, strict native OpenSpec validation and `git diff --check`. Tests cover real pointer composition, favicon, batch persistence and cursor retries, submit while waiting, timeout/disconnect, active reuse, private IPC boundaries, agent refresh/browser update and draft preservation. The installed package exercises the same interfaces. Actual outcomes and performance samples live in docs/verification.md; mission progress stays in the private mission ledger. No remote publication or release is implied by completion.

## Optional performance follow-ups

The complete-change measurements in docs/verification.md identify native subprocess startup as the dominant measured cost. A later measured optimization may verify whether one status response can replace context/list while preserving store/root diagnostics. Smaller mutation responses and lazy artifact loading are other experiments for larger changes. These are optional optimization ideas, not missing acceptance requirements. Existing source hashes, durability and native discovery stay intact. No compression layer, native binary, background daemon or extra cache is justified by current measurements.

## Automatic source and conversation updates

Native directory watches register only real directories within the selected canonical change, skip symlinks and stop at a bounded directory count. Directory events survive file-level atomic replacement. A short debounce and single-flight refresh coalesce writer bursts; directory registration is refreshed to cover newly created subdirectories. Native context/list/status still determines served artifacts. Identical manifest/source fingerprints produce no write or browser rerender. Errors retain the previous valid review and expose manual retry; shutdown closes watches and pending timers before releasing ownership.

Observed conversation activity lives in an optional format-1 activity map keyed by batch ID, outside immutable batch entries. CLI receipt records receivedAt only after a batch is successfully decoded; offline retrieval remains possible without falsely creating an active-reader receipt. An explicit reply command reports working or posts terminal plain-text feedback. Working is never inferred from a changed file. Reply history is retained and identical retried terminal replies are idempotent. Browser activity updates refresh feedback UI without replacing the document or disturbing a selected range/draft.

A source update automatically refreshes the view, preserves written drafts and scroll context, and reconciles anchors. An activity update alone preserves the document/selection. Presence distinguishes a waiting CLI from no listener; a submitted batch remains queued while no CLI is waiting, including while the agent is working. The first-party skill instructs the existing conversation to remain in bounded waits while the operator requests review, explicitly report work, revise/validate, reply and return to waiting. It cannot interrupt or wake a stopped/ended model, inject terminal keystrokes, kill an agent or infer approval. Harness-specific steering would be a separate explicit integration, not a portable CLI claim.
